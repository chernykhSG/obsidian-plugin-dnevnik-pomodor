# Дизайн плагина «Дневник помодоро» (dnevnik-pomodoro)

Дата: 2026-11-10
Статус: утверждён пользователем (brainstorming)

## 1. Назначение

Один Obsidian-плагин закрывает все функциональные требования ТЗ «Дневник работы»
(R1–R8) и заменяет стек из пяти комьюнити-плагинов: QuickAdd, Status Bar Pomodoro,
Periodic Notes, Dataview, Pomodoro Timer (eatgrass).

Ключевой принцип ТЗ сохранён: **минимальное трение в моменте** — по завершении
рабочего интервала плагин сам открывает окно ввода сводки (ноль действий
пользователя), сводка пишется в сегодняшнюю ежедневную заметку.

## 2. Требования, которые закрывает плагин

- R1. Таймер «работа 30 / перерыв 5» (длительности настраиваются), виден в статус-баре и в плавающем окне.
- R2. По истечении рабочего интервала — звук + системное уведомление.
- R3. Окно ввода сводки: автоматически по истечении таймера (основной путь) или по хоткею (запасной путь).
- R4. Многострочный ввод списка; подтверждение — кнопка «Сохранить» (Enter = новая строка, Cmd/Ctrl+Enter = сохранить).
- R5. После сохранения блок появляется в сегодняшней ежедневной заметке мгновенно; заметка создаётся по шаблону, если её нет.
- R6. Время начала блока = (время окончания − длительность помодоро); если в заметке уже есть блоки — не раньше конца последнего блока.
- R7. Статистика по дням месяца/года в собственном окне.
- R8. Работает офлайн; только собственный плагин.

## 3. Архитектура

Проект — отдельная папка вне хранилища Obsidian, чтобы `node_modules` не попадал
в хранилище. Сборка (esbuild) выкладывает `main.js` в `.obsidian/plugins/dnevnik-pomodoro/`.

- Исходники: `/Users/s.chernykh/Ежедневник/плагин-дневник/`
- Сборка: `/Users/s.chernykh/Ежедневник/Дневник работы/.obsidian/plugins/dnevnik-pomodoro/`
- Технология: TypeScript + esbuild (официальный образец obsidian-sample-plugin), npm.

### Модули (`src/`)

| Модуль | Ответственность |
| --- | --- |
| `main.ts` | Точка входа. Регистрация ленты-иконки, команд, настроек, загрузка модулей. |
| `settings.ts` | Настройки: длительность работы/перерыва (мин), звук вкл/выкл, папка и шаблон дневника. Дефолты: 30/5, папка `Ежедневник`, шаблон `Шаблоны/Ежедневная.md`. |
| `timer.ts` | Единая логика отсчёта. Статус-бар + плавающая панель (ItemView). Состояния: остановлен / запущен / пауза. Звук (Web Audio beep) + системное `Notification` по завершении работы. |
| `timer-view.ts` | Плавающая панель таймера: отсчёт, текущий режим, управление, редактирование длительностей. |
| `capture-modal.ts` | Модалка ввода сводки: textarea, Enter=новая строка, кнопка «Сохранить» + Cmd/Ctrl+Enter. Возвращает список строк. |
| `daily.ts` | Запись блока в дневник: путь, создание заметки по шаблону, вычисление времени начала (R6), аппенд блока в конец. |
| `stats.ts` | Парсер дневных заметок: сбор #помодоро и минут по дням/месяцам. |
| `stats-modal.ts` | Окно статистики: выбор месяца/года, таблица «день \| #помодоро \| минуты \| ссылка на день». |

### Управление таймером (состояния плавающей панели)

- **Остановлен (idle):** поля длительности (работа/перерыв) доступны для редактирования; кнопка «Старт».
- **Запущен:** поля длительности **заблокированы**; доступны «Пауза» и «Стоп» (полная остановка и сброс).
- **Пауза:** отсчёт заморожен, остаток сохранён; доступны «Продолжить» и «Стоп».
- **Стоп:** полная остановка и сброс к текущим длительностям; поля разблокируются.

Изменение времени — только в состоянии «остановлен». Во время работы — только пауза либо остановка со сбросом.

### Основной поток (R3, R5)

1. Таймер достигает 0 в рабочем режиме → звук + уведомление.
2. Плагин сам открывает модалку ввода сводки (основной путь, ноль действий).
3. Пользователь печатает список, жмёт «Сохранить».
4. `daily.ts` вычисляет время начала по R6, создаёт заметку при необходимости, дописывает блок в конец.
5. Настройка автозапуска перерыва (автоматически/вручную) — в настройках.

### Правило времени начала блока (уточнение R6)

Так как таймер — собственный, время начала блока берётся **фактическое** (момент
запуска рабочего интервала по настенным часам), а не вычисляется как «конец − 30 мин».
При паузе фактический интервал длиннее длительности — это корректно отражается в блоке.
Ограничение R6 сохраняется: если фактическое начало раньше конца последнего блока
в заметке (например, сводка прошлого помодоро не была подтверждена вовремя), начало
поднимается до конца последнего блока.

## 4. Формат данных (наследуется из ТЗ 4.2)

Ежедневная заметка `Ежедневник/YYYY-MM-DD.md` по шаблону `Шаблоны/Ежедневная.md`:

```markdown
---
type: день
date: 2026-11-10
pomodoros:
---

# вторник, 10.11.2026

## Лента дня
```

Блок помодоро (аппендится в конец заметки):

```markdown
## 🍅 HH:mm — HH:mm

- <пункт 1>
- артефакт: [[ссылка]] или URL
```

Статистика парсит заголовки `## 🍅 …` в дневных заметках.

## 5. Команды и лента

- Лента-иконка (риббон): открыть/свернуть плавающую панель таймера.
- Команда «Открыть сводку помодоро» (хоткей) — запасной путь к модалке ввода.
- Команда «Открыть статистику».
- Команды «Таймер: старт/пауза/стоп».

## 6. Настройки (пользовательские)

- Длительность работы (дефолт 30 мин) и перерыва (дефолт 5 мин).
- Звук по завершении: вкл/выкл.
- Системное уведомление: вкл/выкл.
- Автозапуск перерыва после сводки: вкл/выкл.
- Папка ежедневных заметок (дефолт `Ежедневник`), формат имени, шаблон.

## 7. Судьба текущих плагинов

Отключить и удалить из `.obsidian/plugins/`: `quickadd`, `periodic-notes`, `dataview`,
`obsidian-statusbar-pomo`, `pomodoro-timer`. Оставить только `dnevnik-pomodoro`.

## 8. Тестирование

- Unit-тесты (запуск через `node`, без Obsidian): логика R6 (время начала), парсер
  статистики (парсинг блоков `## 🍅 …`).
- Ручная проверка в Obsidian: таймер→звук→авто-окно→запись блока→статистика.

## 9. Критерии приёмки (из ТЗ 7)

1. Таймер виден в статус-баре и плавающем окне, 30/5, сигнал по истечении.
2. От сигнала до окна ввода — ноль действий (основной путь).
3. Многострочный список целиком попадает в блок.
4. В блоке корректное время начала (−30 мин) и окончания; не раньше конца последнего блока.
5. Первая сводка создаёт ежедневную заметку по шаблону.
6. Окно статистики показывает помодоро по дням месяца/года.
7. Система переживает перезапуск Obsidian без потери данных.
